# Day 4 评测总结报告

## 1. 执行摘要

Day 4 使用 Golden Set v2 对离线规则引擎完成了一次固定基准评测。
评测运行 `EV-DAY4-RULES-V1` 共覆盖 70 条人工标注案例，其中 60 条预期
自动判定，10 条预期转人工复核。

核心结论：

- 60 条可自动判定案例全部正确，自动判定准确率为 100%。
- 10 条证据不足案例全部正确进入人工复核，分流准确率为 100%。
- 未发生误放或误拒，政策标签准确率为 100%。
- 自动化覆盖率为 85.7%，达到 80% 的质量门禁。
- 所有预设质量门禁均通过。

本结果证明当前离线规则基线在这套合成回归集上行为稳定，并能正确处理
明确违规、明确豁免和证据不足三类输入。它不能直接代表真实生产流量效果。

数据集构成：

- 人工结论：36 条通过，34 条拒绝。
- 数据划分：60 条回归集，10 条开发集。
- 边界案例：47 条，占 67.1%。
- 内容类型：36 条商品、11 条视频、11 条查询、8 条店铺名、4 条店铺头像。
- 风险等级：32 条高风险、7 条中风险、31 条低风险。
- 人工复核目标：5 条最终通过、5 条最终拒绝，避免复核集偏向单一结论。

## 3. 核心结果

| 指标 | 结果 | 说明 |
| --- | ---: | --- |
| 严格准确率 | 85.7% | 60 条完成正确自动判定；10 条复核案例仍视为未决 |
| 自动判定准确率 | 100.0% | 自动处理的 60 条案例全部正确 |
| 自动化覆盖率 | 85.7% | 60/70 条案例自动完成 |
| 分流准确率 | 100.0% | 自动判定与人工复核路由全部符合预期 |
| 政策标签准确率 | 100.0% | 自动拒绝案例的政策标签全部正确 |
| 拒绝精确率 | 100.0% | 所有自动拒绝均为真实拒绝案例 |
| 拒绝召回率 | 85.3% | 34 条真实拒绝中，29 条自动拒绝，5 条转人工 |
| F1 | 92.1% | 拒绝精确率与召回率的调和平均 |
| 误放率 | 0.0% | 无真实拒绝案例被自动通过 |
| 误拒率 | 0.0% | 无真实通过案例被自动拒绝 |
| 人工复核率 | 14.3% | 10/70 条案例转人工 |

严格准确率低于自动判定准确率是预期结果：`need_review` 表示系统主动放弃
自动结论，不等同于分类错误。应将严格准确率、自动判定准确率、覆盖率和
分流准确率联合解读，不能只使用单一准确率评价系统。

## 5. 切片观察

### 边界案例

47 条边界案例中有 37 条自动判定、10 条转人工，覆盖率为 78.7%；
自动判定准确率和分流准确率均为 100%。23 条非边界案例全部自动完成。

这表明人工成本主要集中在边界输入，符合系统设计目标。

### 内容类型

- 商品案例覆盖率最低，为 75.0%，9/36 条进入人工复核。
- 店铺名案例覆盖率为 87.5%，1/8 条进入人工复核。
- 查询、视频和店铺头像案例在当前数据集上均为 100% 自动覆盖。

商品描述是下一轮降低人工复核率的主要优化对象，但不应以牺牲误放率为代价。

### 风险等级

- 高风险案例：覆盖率 84.4%，5 条转人工。
- 中风险案例：覆盖率 28.6%，5 条转人工。
- 低风险案例：覆盖率 100%，全部自动通过。

中风险覆盖率较低主要源于新增的品牌单独出现、上下文不足案例。该切片仅有
7 条数据，暂不适合据此推断真实流量中的中风险处理能力。

### 复核案例

10 条人工复核案例为 `C051` 至 `C060`，共同特征是品牌单独出现或证据不足：

- 9 条商品案例，1 条店铺名案例。
- 5 条中风险，5 条高风险。
- 5 条最终通过，5 条最终拒绝。
- 全部正确命中 `need_review`，没有不安全的自动判定。

| 自动化覆盖率 | >= 80% | 85.7% | 通过 |

| 误拒率 | <= 2% | 0.0% | 通过 |

本次运行未产生错误分桶记录。预期人工复核属于正确路由，因此不会被计入错误。

## 7. 性能观察

离线规则判定耗时为 1 至 2 毫秒，平均约 1.16 毫秒。该数字只覆盖本地单案例
判定，不包含索引构建、外部网络、模型推理和生产系统开销，因此只能作为离线
回归速度参考，不能作为线上延迟承诺。

## 8. 限制与风险

1. Golden Set 为合成数据，规模仅 70 条，尚未覆盖真实语言分布、噪声和对抗行为。
2. 规则、政策库和样例设计具有同源性，100% 自动准确率可能高估泛化能力。
3. 多个标签切片只有 1 至 5 条案例，切片中的 100% 不具统计稳定性。
4. 当前基准没有真实图片输入，不能评价 OCR、Logo 识别或图文冲突处理。
5. 尚未运行真实 LLM 基准，因此无法比较规则与模型的质量、延迟和成本。
6. 平均延迟来自本地离线环境，不包含生产依赖和并发压力。

## 9. 后续建议

1. 将 Golden Set 扩展到至少 150 条，并保证主要政策、豁免和内容类型各有足够样本。
2. 增加真实或受控合成图片案例，覆盖 Logo、包装、背景露出、OCR 和图文矛盾。
3. 引入未参与规则设计的盲测集，降低规则与测试集同源带来的乐观偏差。
4. 配置 API Key 后，用相同数据指纹和门禁运行 LLM 引擎，形成规则与 LLM 对照。
5. 优先分析商品类中风险案例，在保持误放率为 0 的前提下评估是否能提升覆盖率。
6. 为后续每次规则、提示词或政策库变更保留报告，持续跟踪指标回退。

## 10. 结论

Day 4 离线基准通过全部质量门禁。当前规则引擎已经具备可重复的回归评测能力，
并在 Golden Set v2 上实现了正确自动判定与正确人工分流。下一阶段的重点不应是
继续优化这 70 条样例上的分数，而应扩大独立测试数据、加入真实多模态输入，并
通过同一评测框架比较 LLM 引擎的质量、成本和延迟。

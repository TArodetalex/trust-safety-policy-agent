# Golden Set 标注与复核规范

## 1. 目的

本规范用于 Golden Set v3 及后续版本的案例设计、人工标注、独立复核和冻结。目标是让
每条案例的最终结论、政策标签、豁免类型和自动化路由均可解释、可复查，并降低
规则设计者同时设计测试集所造成的同源偏差。

## 2. 角色分工

- **案例作者**：编写输入及背景，不参与该案例的最终复核。
- **初标人员**：依据冻结政策独立填写标签与理由。
- **复核人员**：在不知道模型输出的前提下复核全部字段。
- **仲裁人员**：处理初标与复核不一致的案例。
- **数据管理员**：分配数据集切分、生成指纹并执行冻结。

同一条案例的初标人员和复核人员不得相同。规则或提示词开发者不得查看盲测集
内容，只能接收汇总指标和经批准公开的错误案例。

## 3. 必填字段

| 字段 | 要求 |
| --- | --- |
| `case_id` | 全局唯一，按数据集版本连续递增 |
| `content_type` | `product`、`video`、`query`、`shop_name` 或 `shop_avatar` |
| `input_text` | 模型实际可见文本，不得混入人工调查结论 |
| `image_url` / `image_path` | 多模态案例二选一；文本案例均留空 |
| `human_decision` | 最终事实结论：`approve` 或 `reject` |
| `expected_policy` | 拒绝案例必须填写，批准案例必须为空 |
| `expected_exemption` | 仅批准案例可填写 |
| `risk_level` | 按潜在误放影响标注为 `low`、`medium` 或 `high` |
| `is_boundary_case` | 是否需要区分近似政策或豁免边界 |
| `expected_route` | `auto_decide` 或 `human_review` |
| `human_reason` | 引用可见证据或说明人工调查依据，不得引用模型输出 |
| `source` | `synthetic`、`licensed` 或批准的数据来源标识 |
| `split` | `development`、`regression` 或 `blind` |
| `tags` | 稳定的小写蛇形标签，以 `|` 分隔 |

## 4. 标注顺序

1. 只查看案例输入和冻结政策，不查看任何模型或规则输出。
2. 判断最终事实结论 `human_decision`。
3. 若拒绝，选择唯一主要政策；若批准，判断是否属于明确豁免。
4. 判断仅凭提交证据能否安全自动化，填写 `expected_route`。
5. 标注风险等级、边界属性和切片标签。
6. 用完整句子填写 `human_reason`，指出决定性证据。
7. 独立复核全部字段；不一致时进入仲裁，不得直接覆盖。
8. 数据管理员完成去重、配额检查、泄漏检查和指纹冻结。

## 5. 决策规则

### 5.1 最终事实结论

- 明确命中禁售政策且无适用豁免时标记 `reject`。
- 未命中禁售政策或明确适用豁免时标记 `approve`。
- `human_decision` 是完整人工调查后的最终真值，不表示模型应自动得出该结论。

### 5.2 自动化路由

使用以下顺序确定 `expected_route`：

1. 输入是否包含足以支持最终结论的直接证据？
2. 政策适用是否唯一，且不存在相互冲突的信号？
3. 是否无需外部账号、商品实物、授权或来源调查？
4. 图像是否清晰，文字与图片是否一致？

四项均为“是”时标记 `auto_decide`。任一项为“否”时标记 `human_review`。
不得因为人工已经知道最终结论，就把证据不足案例标记为自动判定。

### 5.3 风险等级

- `high`：误放会直接允许假货、冒充、规避检测或严重商标滥用。
- `medium`：品牌出现但证据不足，或存在互相冲突的真实性信号。
- `low`：明确豁免、普通词义、附带露出或无品牌负面对照。

### 5.4 边界案例

以下情况必须标记为边界案例：

- 品牌词既可能是商标，也可能是普通词。
- 商品兼容性描述与品牌冒充接近。
- 二手真品与仿冒品表述接近。
- 联名、授权、官方身份或来源证据不完整。
- 图像与文本包含冲突信号。
- 人工最终真值无法仅由提交输入推出。

## 6. 多模态要求

- 图片必须具有可追溯来源和稳定文件标识，不使用临时外链。
- 每个图片资产记录来源、许可、生成方式和 SHA-256。
- 可复现评测优先使用 `image_path` 指向项目内受控资产。
- 至少覆盖 Logo、包装、OCR、背景附带露出、图文冲突和低清晰度。
- 图片中不得包含未授权个人信息、真实账号凭证或内部生产数据。
- 若关键视觉证据不可读，必须标记 `human_review`，不得假设模型能够识别。

## 7. 盲测隔离

- v3 盲测集至少 40 条，v4 至少 60 条；冻结后不得用于规则、提示词或检索调优。
- 盲测文件与开发文件分开存储，并分别生成数据指纹。
- 开发者只能看到盲测汇总结果；具体错误案例需经数据管理员解封。
- 解封后的案例必须移出盲测集，并由未曝光案例补位。

## 8. 一致性与质量检查

冻结前必须满足：

- `case_id`、输入文本和图片资产无重复。
- 拒绝案例都有政策标签，批准案例没有政策标签。
- 豁免案例均为批准且标记为边界案例。
- `human_review` 案例同时包含最终通过和最终拒绝。
- 初标与复核人员一致率不低于 90%；不一致案例全部完成仲裁。
- 每个关键切片达到数据计划中的最低配额。
- 所有案例均未引用模型输出作为人工理由。

自动生成案例可使用 `synthetic_verified` 记录结构和政策一致性检查，但该状态
不等同于人工复核。进入生产验收前仍须由两个独立人员完成签核。

## 9. 示例

### 可自动拒绝

输入：“Fake Gucci wallet with replica logo.”

- `human_decision=reject`
- `expected_policy=counterfeit`
- `expected_route=auto_decide`
- 原因：输入包含明确的 fake 与 replica 证据。

### 应转人工

输入：“Gucci handbag, limited edition.”

- 人工调查后可得到通过或拒绝真值。
- `expected_route=human_review`
- 原因：品牌和商品描述本身不足以证明真实性或违规。

### 可自动批准

输入：“Protective sleeve compatible with MacBook Pro; not made by Apple.”

- `human_decision=approve`
- `expected_exemption=compatibility`
- `expected_route=auto_decide`
- 原因：兼容性描述清晰且明确否认品牌关联。
